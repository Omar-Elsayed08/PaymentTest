# Everything Burger

Static shop site with a Stripe Checkout backend. Runs locally on Node, deploys
free to Cloudflare Workers.

## Why there is a backend at all

Everything in `shop/js/` runs in the shopper's browser and can be edited with
devtools, so prices can never be trusted from there. The cart only ever sends
product ids, sizes, and quantities. Prices are looked up server-side in
`backend/shared/catalog.js`, which is also the only place the Stripe secret key
exists.

## Layout

Everything the browser downloads lives at the top level. Everything that
touches Stripe lives under `backend/` and is never served to visitors.

| Path | Purpose |
|---|---|
| `index.html`, `shop/`, `gallery/`, `about/`, `assets/` | the public site |
| `shop/**-data.js` | product definitions, the only place to edit products |
| `backend/shared/` | checkout logic used by both runtimes |
| `backend/worker/index.js` | Cloudflare entry point (production) |
| `backend/server/` | Express entry point (local development) |
| `backend/scripts/` | build steps |
| `wrangler.toml` | Cloudflare deployment config |

`backend/shared/catalog-data.js` and `dist/` are generated by `npm run build`.
Don't edit them by hand.

## Local development

```bash
npm install
cp .env.example .env      # then fill in your Stripe test keys
npm start
```

Open http://localhost:3000. Opening the HTML files directly will not work,
because checkout needs the API on the same origin.

To test webhooks, in a second terminal:

```bash
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

Copy the `whsec_…` it prints into `STRIPE_WEBHOOK_SECRET` and restart the
server. Pay with test card `4242 4242 4242 4242`, any future expiry, any CVC.
Paid orders append to `backend/server/var/orders.jsonl`.

To run the Cloudflare version locally instead:

```bash
cp .env .dev.vars         # wrangler reads secrets from .dev.vars
npm run cf:dev            # http://localhost:8787
```

Set `PUBLIC_BASE_URL=http://localhost:8787` inside `.dev.vars`.

## How hosting works (not GitHub Pages)

GitHub Pages can only serve static files. Stripe checkout needs a backend that
holds the secret key and looks up prices, so the live shop is **one Cloudflare
Worker**: HTML from `dist/` plus `/api/*` on the same origin.

GitHub is the source of truth. Every push to `main` runs
`.github/workflows/deploy.yml`, which builds the site and deploys the Worker.
That is what gives you a custom domain on the checkout URLs.

Do not turn on GitHub Pages for this repo. If a custom domain already points
at Pages, move that hostname onto the Worker instead.

## One-time setup

Do these steps once. After that, `git push` is the deploy.

### 1. Cloudflare account

Create a free account at [dash.cloudflare.com](https://dash.cloudflare.com).

### 2. GitHub secrets so Actions can deploy

1. In Cloudflare, open **Workers & Pages** → **Overview**. Copy the
   **Account ID** from the right sidebar.
2. Create an API token at
   [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)
   using the **Edit Cloudflare Workers** template.
3. In GitHub, open `omar-elsayed08/paymenttest` → **Settings** →
   **Secrets and variables** → **Actions** and add:

| Secret | Value |
|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | the Account ID from step 1 |
| `CLOUDFLARE_API_TOKEN` | the token from step 2 |

Those two secrets are only for deploying. They are not Stripe keys.

### 3. First deploy

Commit the backend, `wrangler.toml`, and `.github/workflows/deploy.yml`, then
push to `main`. GitHub Actions will build and publish
`https://everything-burger.<your-subdomain>.workers.dev`.

Open the Actions tab and confirm the deploy job is green. Visit
`/api/health` on that URL. You should get JSON. Checkout will still fail
until Stripe secrets are set.

You can also deploy from your laptop after `npx wrangler login`:

```bash
npm run cf:deploy
```

### 4. Link Stripe (test mode first)

1. Open [dashboard.stripe.com/test/apikeys](https://dashboard.stripe.com/test/apikeys)
   and copy the **Secret key** (`sk_test_…`).
2. Store it on the Worker, not in GitHub:

```bash
npx wrangler secret put STRIPE_SECRET_KEY
```

Paste the test secret when prompted. Or in the Cloudflare dashboard: the
`everything-burger` Worker → **Settings** → **Variables and Secrets**.

3. In Stripe, go to **Developers** → **Webhooks** → **Add endpoint**.
   URL:

   `https://everything-burger.<your-subdomain>.workers.dev/api/webhooks/stripe`

   Listen to `checkout.session.completed` only.
4. Reveal the endpoint **Signing secret** (`whsec_…`) and store it:

```bash
npx wrangler secret put STRIPE_WEBHOOK_SECRET
```

This `whsec_` is not the same value the Stripe CLI prints locally.

5. Set `PUBLIC_BASE_URL` in `wrangler.toml` to the exact origin shoppers will
   use (no trailing slash), then push so Actions redeploys. Stripe success and
   cancel links are built from that value.

Pay with test card `4242 4242 4242 4242`, any future expiry, any CVC.

### 5. Custom domain

The Worker already has a `*.workers.dev` URL. To put checkout on your own
hostname:

1. Add the domain to Cloudflare (**Add a site**) and switch the nameservers
   at your registrar if Cloudflare asks you to.
2. In `wrangler.toml`, uncomment the `routes` line and put your hostname:

```toml
routes = [{ pattern = "shop.yourdomain.com", custom_domain = true }]
```

3. Change `PUBLIC_BASE_URL` to `https://shop.yourdomain.com`.
4. Push to `main`. The deploy attaches the hostname and Cloudflare issues
   the certificate.
5. In Stripe, edit the webhook URL to
   `https://shop.yourdomain.com/api/webhooks/stripe`.

Stripe Checkout itself stays on `checkout.stripe.com`. Your custom domain is
the shop, the success page, and the webhook. That is what shoppers see before
and after they pay.

## Going live

Test keys never move real money. When ready:

- Switch off test mode in Stripe and complete their account activation
- Replace the secret with the live key: `npx wrangler secret put STRIPE_SECRET_KEY`
- Create a live-mode webhook endpoint and store its signing secret the same way
- Confirm `PUBLIC_BASE_URL` matches your real domain over HTTPS

Stripe charges roughly 2.9% + 30¢ per card payment. Hosting stays free within
Cloudflare's 100,000 requests per day.

## Orders

On Cloudflare there is no writable disk, so paid orders are logged to
`wrangler tail` output rather than a file. The durable record is the Stripe
Dashboard, which stores every payment with the shipping address and a `cart`
metadata field describing what was bought. Enable Stripe's email notifications
to get told about each sale.

## Configuration

Non-secret settings live in `[vars]` in `wrangler.toml` for production, and in
`.env` locally.

| Variable | Default | Meaning |
|---|---|---|
| `PUBLIC_BASE_URL` | — | origin used for Stripe redirects |
| `CURRENCY` | `usd` | Stripe currency code |
| `SHIPPING_CENTS` | `800` | flat shipping, `0` for free |
| `MAX_QTY_PER_LINE` | `20` | per-line quantity cap |
| `MAX_CART_LINES` | `30` | distinct items per order |
| `ALLOWED_SHIPPING_COUNTRIES` | `US,CA` | Stripe country allowlist |
